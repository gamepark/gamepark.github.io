# Release notes v7.7

## Breaking change: game options are declared with `OptionsSpecV2`

A game now declares its options as a plain JSON structure, with no functions and no text. The platform
copies that declaration into its database when your bundle is prepared, so every screen reads what your
game can be configured with instead of downloading and running the bundle to show three labels.

```typescript
export const GameTemplateOptionsSpecV2: OptionsSpecV2 = {
  specVersion: 2,
  players: { min: 2, max: 4 },
  identities: { values: getEnumValues(PlayerColor) }
}
```

Three things leave the game with it:

- **Labels and help texts** move to `app/public/options/{locale}.json`, published beside your
  translations, under keys derived from the spec (`option.<option>`, `identities.<value>`, …).
- **`subscriberRequired`, `competitiveDisabled` and `competitivePlayers`** move to the platform database,
  so Game Park can change them without you releasing again.
- **`validate` is gone.** Constraints are declared as `playerCount`, `requires`, or a
  `forbidden-combination` rule. A declaration the platform can read is one it can search, so an
  impossible combination is now reported as the rule that forbids it rather than as an exception thrown
  from inside your game — and the platform can propose a valid set of options instead of retrying blindly.

The whole catalogue has been migrated. See [Game options](features/game-options.md) for the reference,
and the [migration guide](troubleshooting/v7.7-migration-guide.md) for the steps.

## Breaking change: translations are now stored in git

Translations are no longer loaded from a centralized S3 bucket (`translations.game-park.com`). Each game must now host its own translation files in the repository.

### What changed

- **Game translations** must be placed in `app/public/translation/{locale}.json` (e.g. `en.json`, `fr.json`)
- The game namespace is loaded from the game's own origin (`/translation/{locale}.json`)
- **Common translations** (`common`, `credits`) are now loaded from the main Game Park website instead of S3

### Migration steps

1. **Download your game's translations** from S3: `https://translations.game-park.com/{locale}/{game}.json` (e.g. `https://translations.game-park.com/en/mythologies.json`)
2. Create the directory `app/public/translation/`
3. Save each locale file as `en.json`, `fr.json`, etc.
4. Each file is a flat key-value object with your game's translation keys:
```json
{
  "card.1": "Knight",
  "card.2": "Archer",
  "header.play": "{player} plays a card"
}
```
5. **Redeploy** your game — the translation files are deployed automatically with `yarn deploy` (rclone syncs the `public/` directory)

### Missing keys

Missing translation keys are now logged as warnings (dev) or errors (production) in the console, and captured by Datadog. The old `/api/translations/missing` endpoint still exists for backward compatibility but only logs errors — it no longer stores keys in a database.

During development, you can write translations only in your native language. Translations to other languages will be done later. Add `?locale=fr` (or `es`, `en`...) to the URL to test the texts in your language.
