# Migration to framework v7.7

## Game options are declared with `OptionsSpecV2`

The full reference is in [Game options](features/game-options.md). The steps:

1. Replace `OptionsSpec<YourOptions>` with `OptionsSpecV2`, and add `specVersion: 2` plus `players`
   (`{ min, max }` — it must match the player count declared for your game on the platform).
2. Turn each option into `{ kind: 'boolean' | 'enum' | 'enum-set', values }`. Keep referencing your own
   enums: `values: getEnumValues(Mythology)` rather than a list of numbers.
3. Move `players.id` to `identities`, and `players.team` to `teams`.
4. Move every `label`, `help` and `warn` text into `app/public/options/{locale}.json`, keyed by
   convention — `option.<option>`, `option.<option>.<value>`, `identities.<value>`, and their `.help`
   variants. Values are addressed by their value, so `PlayerColor.Blue = 1` becomes `identities.1`.
5. Rewrite `validate` as `playerCount` on an option or a value, `requires` on a value, or a
   `forbidden-combination` rule. Keep the i18n key your `OptionsValidationError` used as the rule's
   `message`: it is resolved in the same options document, so your wording is preserved word for word.
6. Delete `subscriberRequired`, `competitiveDisabled` and `competitivePlayers`, and tell Game Park what
   your game needs — they are held in the platform database now.
7. Export the new constant from `rules/src/index.ts`, and pass it to `<GameProvider optionsSpec={…}>`.
8. Set `"@gamepark/rules-api": ">=7.7"` in the `peerDependencies` of `rules/package.json`.

:warning: Do not keep the v1 declaration "just in case". The platform reads only the v2 one, so a stale
v1 spec is a second source of truth that will drift.

:bulb: If a player can have no name in your game — a bot, or a player who is not signed in — check that
your options document carries `identities.<value>`. That is what names them now.

## Translations are now stored in git

Translations are no longer loaded from the S3 bucket (`translations.game-park.com`). Each game must now host its own translation files in the repository.

### Migration steps

1. **Download your game's translations** from S3: `https://translations.game-park.com/{locale}/{game}.json` (e.g. `https://translations.game-park.com/en/mythologies.json`)
2. Create the directory `app/public/translation/`
3. Save each locale file as `en.json`, `fr.json`, etc.
4. Each file is a flat key-value object with your game's translation keys:
```json
{
  "card.1": "Knight",
  "card.2": "Archer",
  "header.play": "{player} plays a card"
}
```
5. **Redeploy** your game — the translation files are deployed automatically with `yarn deploy` (rclone syncs the `public/` directory)

:warning: Do not include common translations (`common`, `credits`) in your files — they are now loaded from the main Game Park website.

### Missing keys

Missing translation keys are logged as warnings (dev) or errors (production) in the console, and captured by Datadog.

:bulb: During development, you can write translations only in your native language. Translations to other languages will be done later. Add `?locale=fr` (or `es`, `en`...) to the URL to test the texts in your language.
